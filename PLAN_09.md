## Items
1. **Deferred busy beats.** When a heartbeat is due and the target is busy (`working` or `blocked` per the existing `hcx ls --json` pre-check), do not drop it. Re-check the target status every 3 s (env `AGENT_SHELL_BUSY_POLL_MS` for tests, minimum 200 ms) and send ONE beat as soon as the target is not busy, using the job's latest last line at send time. The wait ends at a deadline of 80% of the current heartbeat interval after the beat was due (so beats never pile up or overlap the next one); if the target is still busy at the deadline, count it as `heartbeats_skipped_busy` as today (not a failure). A beat that was delayed and then sent counts as sent and also increments a new counter `heartbeats_deferred` (status.json, show text and --json; old files default to 0). While waiting, the job's completion still wins: if the job finishes during the wait, drop the pending beat (the completion turn replaces it) without counting it. A back-off-suppressed beat (unchanged output) is never deferred. Polling must not block the job's supervision (no busy loop; one `hcx ls` per poll, 5 s timeout; stop polling when the job ends).
2. **Say when the next progress comes.** Every progress turn ends with the next expected beat, e.g. `shell job 'x' still running (40.3s elapsed). Last line: tick 9. Next progress in ~10s.` using the current (possibly backed-off) interval, rounded sensibly (`~10s`, `~2m`, `~24s`). Heartbeat-fixed and disabled-heartbeat jobs: same wording only when another beat is scheduled. The completion turn is unchanged.
3. **show/check wording.** The compact heartbeat line becomes `heartbeats sent S (deferred D), skipped K (backoff B, busy U), failed F`; JSON adds `heartbeats_deferred`.
